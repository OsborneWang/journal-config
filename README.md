# journal — 个人日志 / 今日看板 / 日报 / 月报

```
├─ ~/journal/                    数据（本地 git 仓库，不推远端）
│   2026/11/2026-11-09.md        一天一个文件
│   reports/2026-11.md            月报
└─ ~/journal-config/             本仓库 = 安装源（所有文件都是软链出去的）
    journal.py                   全部实现，单文件、零第三方依赖
    bin/                         j / j-board / j-capture / j-browse / j-chat / …
    prompts/                     distill / report / week / month 四个提示词
    config.sh                    配置（模型、仓库根、开关）
                                 · 本机私有的值写到 ~/.config/journal/config.local.sh
    chat.md                      日志助手（popup 里的临时 pi）的系统提示
    skills/journal/              给普通 pi 会话用的 skill
    install.sh                   装到 ~/.local/bin 与 ~/.config/journal
    check.sh                     自检（安装 + 冒烟 + 离线回归）
    tests/smoke.sh               41 项离线回归（2 秒，不调模型）
    eval/                        提示词评测用例与 runner
    AGENTS.md                    给 agent 看的：架构、不变量、已知坑
```

**改完不用重装**：`~/.local/bin/j*`、`~/.config/journal/*`、pi 的 skill 都是软链指向本仓库。
改完跑一次 `./check.sh` 就行；改了看板渲染逻辑要 `tmux respawn-pane -k -t <window>.0` 重启看板。

## 三个层次（改任何一层都不影响其他层）

1. **采集**：`j "..."` 只追加，永不被 AI 改写，永不因为 API 失败而丢内容。
2. **结构**：计划项就是 `- [ ]` 行，结转就是复制到明天并 `↺n`。没有数据库、没有 id。
3. **派生**：日报 / 月报是「文件 → 报告」的纯函数，随时可重跑、可换模型重生成。

AI 只在两处出现，且都是**无状态一次性调用**（`pi -p`）：
- 速记后后台整理计划（`distill.md`，便宜模型，只勾选/新增，绝不改写文字）
- 生成日报 / 月报（`report.md` / `month.md`，输出只落到「总结」新区块）

**所有数字由脚本统计，模型只写叙述。**

## tmux 快捷键（prefix 之后）

（记不住就按 `prefix ?`，会弹一页实时从 `~/tmux-config/tmux.conf` 生成的速查表）

| 键 | 作用 |
|---|---|
| `Space` | **记一笔**（主入口，任何窗口可用；原 next-layout 让位）<br>`+`=待办　`!`=计划外完成　不带符号=流水 |
| `a` | 日志助手：临时起一个 pi，把话变成记录，聊完即退 |
| `S` | 生成今日总结（一天可以多次，每次追加一条带时间的总结） |
| `W` | 生成本周周报 |
| `M` | 生成本月月报 |
| `e` | nvim 直接改今天的文件 |
| `X` | **管理 todo**：回车切换完成 · `C-R` 改名 · `C-D` 删除 · `C-P` 从计划外衍生待办 |
| `R` | **开工视图**：上次没做完的 + 上次定的明日计划 + 今天现状 |
| `L` | 浏览 / 搜索全部速记（fzf，右边预览当天，回车 nvim 打开那天） |
| `Y` | yazi 弹窗（取代被看板占掉的左栏） |
| `J` | 跳转 / 新建日志窗口，并保证左边有看板 |
| `B` | **在当前窗口左侧召唤 / 收起看板**（不动任何已有 pane，再按一次收起） |

两种用法，按习惯挑一个：

- **固定窗口**：`prefix J` 开一个专门的日志窗口，看板常驻在左边。适合「坐下来写日志」。
- **就地召唤**：`prefix B` 在当前窗口（比如 window 1）左侧临时插一块看板，再按一次收起。
  它不会杀掉任何已有 pane —— 你的 yazi / pi / shell 都还在，只是被挤窄一点，
  收起后宽度自动还原。适合「干活干到一半抬头看一眼还剩什么」。

看板只读、不接收键盘输入。右上角是 `HH:MM:SS` 时钟，每秒刷新。

两种重绘节奏，互不打扰：

- **内容层**：文件变了 / 窗口尺寸变了才整帧重画（所以不会闪）
- **时钟层**：只把右上角那 8 列原地重写，不动其它任何像素
`prefix =` / `prefix -` 只调整当前窗口的主窗格宽度，不再影响其他窗口。

## 改 todo 状态

四种方式，按顺手程度挑：

| 方式 | 操作 | 适合 |
|---|---|---|
| `prefix X` | fzf 列表里 Tab 多选、回车切换 | 一次勾掉好几项，**最常用** |
| `prefix Space` 打 `- 编号` 或 `- 关键字` | 一行搞定 | 只想动一项 |
| `j done <编号\|关键字>` | 在 shell 里 | 写脚本 / 命令行习惯 |
| `prefix e` | nvim 里把 `- [ ]` 改成 `- [x]` | 批量整理、改文字 |

`prefix X` 里选中的如果是**已完成**的项，回车就是取消勾选——同一个键双向用。

## 命令

```
j "<一句话>"            记一笔速记（后台自动整理计划）
j -n "<一句话>"         记一笔，不动计划（AI 不可用时也可以用这个）
j "+<任务>"             加进 todolist（待办，会结转），不经 AI
j "!<一句话>"           记一条「计划外完成」（干完了、但本来没排的事）
j plan "<任务>"         加一条计划项
j done                  列出今日计划（带编号）
j done <编号|关键字>    切换完成状态
j list [--open]         列成 `编号<TAB>○/✔ 文本`（给 j-toggle 用）
j log [-n N]            今天的速记（默认最近 10 条）
j log -a [-n N]         跨天看速记（可加 2026-11 这种月份过滤）
j search <词>...        跨天搜速记，多个词是 AND
j day [YYYY-MM-DD]      打印某一天整篇
j show                  打印今天整篇
j edit                  用 $EDITOR 打开今天
j status                今天概况 + AI 整理状态
j start                 开工视图（上次没做完的 + 今天的现状）
j report [--dry]        生成今日总结
j week [2026-W45]       生成周报（默认本周）
j month [YYYY-MM]       生成月报
j undo [n] [--dry]      撤销最近 n 次写入（默认 1 次）
j rm <序号> [--extra]   删掉一项计划（--extra 删计划外的）
j rename <序号> [新名]  改一项的文字
j promote <序号> [文本] 从「计划外」衍生一条待办
j backup [--push]       给数据做 git bundle 快照（可顺带推私有远端）
j month [YYYY-MM]       生成月报
j path                  今天文件路径
j distill               立刻跑一次计划整理
j board [--once]        渲染看板（调试用）
```

## 一天的边界从凌晨 4 点算

默认 `J_DAY_START="04:00"`：凌晨 0:00–3:59 记的东西**仍算前一天**。

为什么：晚上 11 点开始写日志、写到 1 点，那时的记录属于"今天"而不是"明天"。
没有这个设置，熬夜写的所有内容会跑到新的一天，还得手工搬。

处在跨夜时段时，看板会显示 `·跨夜`，时钟变黄，提醒你现在的记录算在哪一天。
时间戳仍然写挂钟时间（`- 01:20 ...`），所以文件里能看出真实时刻。

## 备份（别省这一步）

数据在 `~/journal`，只有本地 git。**git 只防手滑，不防磁盘坏**。

```sh
j backup              # 打一个 git bundle 到 ~/journal-backups/，自动校验 + 只留最近 7 份
j backup --push       # 同时推到你配的私有远端（config.local.sh 里设 J_BACKUP_REMOTE）
```

从 bundle 恢复：

```sh
git clone ~/journal-backups/journal-20261110-083000.bundle ~/journal
```

建议直接挂定时任务（数据是隐私内容，远端务必用**私有**仓库）：

```cron
30 22 * * * /home/osborne/.local/bin/j backup --push
```

## 三种记录（别混）

| | 计划项 | 计划外完成 | 速记 |
|---|---|---|---|
| 是什么 | 今天**打算做**的事 | **干完了、但本来没排**的事 | 流水，想到什么记什么 |
| 怎么记 | `prefix Space` 打 `+ 内容` | 打 `! 内容`；或直接说一句，AI 自动判定 | 打一句话，不带符号 |
| 有状态吗 | 有：`[ ]` / `[x]`，可勾 | 没有，永远是「已完成」 | 没有 |
| 跨天吗 | 没做完的带到明天（`↺n`） | 不跨天 | 不跨天 |
| 看板上 | `○` / `✔` | `◆`，计数写成 `4/7 +2` | 底部条数 + 最新一条 |
| 影响完成率吗 | 是 | **否**，单独统计 | 否 |
| 谁在读 | 你 | 日报「今日完成」 | 日报/月报的原料 |

一句话：**计划项是将来时，计划外是"今天的意外产出"，速记是流水账。**

为什么把「计划外」单列：临时被拉去救火、顺手修了个 bug、帮人排查问题，
这些是真产出，但塞进计划会让完成率失真（也让你不敢在计划里定野心大一点的目标）。
所以它们单独一块，日报和月报都把两项分开统计，月报里还会点出
「计划外 N 项」这个数字——它是「你被临时事务打断得多不多」的指标。

## 文件格式

```markdown
# 2026-11-09 周一

## 计划
- [x] 修 pmCloud 导出 Excel 列错位
- [ ] e2e 环境起不来，需要运维        ↺2
## 计划外
- 14:20 帮运维排查了 nginx 502
## 速记
- 09:12 站会：导出问题确认是表头映射错了
## 总结 · 18:32
### 今日完成
...
```

- `↺n` = 结转了 n 天，跨天累计。月报的「拖延榜」就是它的最大值。
- 「总结」区块可以有很多个（一天多次生成），月报只取当天的最后一条做叙述材料，
  但统计用的是全天原始数据。
- 计划项有两种来源：你敲 `+ 任务`（确定性），或后台 AI 从速记里提炼（`add`）。
- 「计划外完成」同理：你敲 `! 内容`，或 AI 从速记里判定成 `done_add` 落进 `## 计划外`。
- 看板标记：`○` 待办 · `✔` 计划内已完成 · `◆` 计划外完成 · `↺n` 结转 n 天。
- 中文输入按退格删一个字：弹窗用 `read -e`（走 readline），`^H` 和 `DEL` 都能删。
- 新的一天第一次写入时，自动把上一天没勾的行复制过来并 `↺+1`。

## 机器视角

日报 / 月报会额外塞给模型一段机器采集的证据：

- `J_REPO_ROOTS` 下（默认 `/WorkSpace /ShareSpace`）自动发现 git 仓库，
  按 `J_GIT_AUTHOR` 过滤当天的提交
- `herdr-projects` 任务板上已完成的条目（**没有日期**，所以提示词要求：
  只有能明显对应今天的工作时才引用）

月报还会用脚本算出：有记录天数、计划完成率、每日完成数、结转最久的 6 项。

## 常改的配置（`~/.config/journal/config.sh`）

| 变量 | 说明 |
|---|---|
| `J_MODEL_CAPTURE` | 速记整理用的模型（默认 `cn:glm-5.3-flash`） |
| `J_MODEL_REPORT` | 日报 / 月报用的模型（默认 `cn:deepseek-v4.1-flash`） |
| `J_AI_CAPTURE` | `0` = 永不在速记后动计划 |
| `J_THINK_CAPTURE` / `J_THINK_REPORT` | 思考档位，提速用 |
| `J_REPO_ROOTS` / `J_GIT_AUTHOR` | 机器视角的范围 |

## 改完怎么验

```sh
./tests/smoke.sh        # 41 项离线回归，2 秒，不碰真实数据、不调模型
./eval/run.py           # 提示词评测（5 个用例，会调模型）
./check.sh              # 安装 + 冒烟；./check.sh --model 连评测一起跑
```

`tests/smoke.sh` 覆盖：逻辑日、前缀语义、边界输入、结转、编辑、撤销、查询、渲染（35 种尺寸）、备份、并发、脏数据。
`eval/run.py` 防的是「换了模型之后 AI 行为悄悄变差」——这类退化不会报错，只会让你的日报慢慢变得不对味。

## 出问题时

- 后台整理没动静：`cat ~/journal/.distill.log`。**每次运行都会留一行**：
  `[10:08:46] ✔+ xxx` 表示补了一条完成项，`[10:08:46] 无变化 · 模型返回 {...}`
  表示模型认为没影响计划（这时原文仍然在速记里，没丢）。
  想看现场报错就手动跑 `j distill`。
- 想回滚：`git -C ~/journal log --oneline`，每次写入都有一次 commit。
- 看板崩了不影响数据：它只读。用 `prefix x` 杀掉这个 pane 即可。
- 看板卡住不动：`tmux respawn-pane -k -t <window>.0 'exec ~/.local/bin/j-board'`。
